公式レジストリは、GitHub 上の静的な JSON のインデックスと、GitHub Releases の配布物で動きます。検索はユーザーの PC で行われます。

## 公開の準備

1. **ID を決める**: `<GitHub ユーザー名>.<名前>` の形にしてください。GitHub アカウントと一致しない名前空間は使えません（`otterm.*` は公式専用です）。
2. **マニフェストを確認する**: `otterm mod doctor <id>` を実行し、警告が残っていないことを確認します。
3. **権限を絞る**: 必要な権限だけを宣言してください。`terminal.write` と `network` は、審査の対象になります。
4. **README とスクリーンショットを用意する**: ストアの画面に表示されます。

## 公開の流れ

1. `otterm mod publish` で `.otmod` とエントリの JSON を作ります（[パッケージ](/mods/packaging/) を参照）。
2. 作者は GitHub アカウントで認証し、ID の所有を確認されます。
3. 配布物は GitHub Releases に置かれます。
4. エントリの JSON を、レジストリのリポジトリへ Pull Request として提出します。
5. 審査が通ると、インデックスに載り、ストアに表示されます。

更新も同じ流れです。バージョンを上げて、新しいエントリを提出します。

## 審査

審査は、権限によって 2 つに分かれます。

| 権限 | 扱い |
| --- | --- |
| `terminal.write` または `network` を持つ | 公開の前に人が審査します |
| それ以外 | 公開後に、利用者からの報告で確認します |

報告が一定数を超えた Mod は、自動で非表示になり、審査に回されます。

## 署名

将来は sigstore によるキーレス署名で配布物を守ります（作者が鍵を管理する必要はありません）。それまでは、レジストリの項目に書かれた `size` と `sha256` で配布物を検証します。`otterm mod publish` が両方を書き込むので、作者が計算する必要はありません。値が合わない配布物はインストールされません。

## 有料の Mod

公式レジストリには、無料の Mod だけが載ります。決済の機能はありません。作者が外部で販売することは禁止されていませんが、レジストリには載せられません。
