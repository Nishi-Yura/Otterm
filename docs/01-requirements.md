# 01. 要件定義（Requirements）

## 1. 機能要件（Functional Requirements）

ID は `FR-<領域>-<番号>` で付番する。優先度は MoSCoW（Must / Should / Could / Won't）。

### 1.1 ターミナル基盤（TERM）

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-TERM-01 | ローカルシェル（bash, zsh, fish, PowerShell 7, Windows PowerShell, cmd, nushell, WSL ディストリ）を PTY 経由で起動・操作できる | Must |
| FR-TERM-02 | VT100 / xterm-256color / TrueColor のエスケープシーケンスを解釈し、一般的な TUI アプリ（vim, htop, tmux, lazygit 等）が正しく動く | Must |
| FR-TERM-03 | Unicode（結合文字、絵文字、CJK 全角）を正しく幅計算して描画する | Must |
| FR-TERM-04 | タブと分割ペイン（縦・横・ネスト）を持つ | Must |
| FR-TERM-05 | スクロールバック（既定 10,000 行、設定で変更）と全文検索 | Must |
| FR-TERM-06 | コピー・ペースト（複数行貼り付け時は確認）、矩形選択、URL / ファイルパスのクリック | Must |
| FR-TERM-07 | 画像プロトコル（Sixel, iTerm2 inline image, Kitty graphics）の表示 | Should |
| FR-TERM-08 | リガチャ対応フォント描画 | Should |
| FR-TERM-09 | セッションの復元（終了時のタブ・CWD・レイアウトを次回起動で再現） | Should |
| FR-TERM-10 | SSH / コンテナへの接続 | Won't（mod で提供） |

### 1.2 シェル統合（SHELL）

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-SHELL-01 | 対応シェルに自動でフックを注入し、「プロンプト開始／コマンド開始／コマンド終了（終了コード）」を otterm が検知できる | Must |
| FR-SHELL-02 | 検知した境界で出力を **ブロック** に区切り、ブロック単位で折りたたみ・コピー・再実行・共有ができる | Must |
| FR-SHELL-03 | 現在の CWD を常に把握し、UI（タブ名、ファイルパネル、パンくず）に反映する | Must |
| FR-SHELL-04 | 実行前のコマンド文字列を取得し、確認レイヤ・ヒント表示に使える | Must |
| FR-SHELL-05 | 統合が効かないシェルでも、通常のターミナルとして動作を継続する（グレースフルデグレード） | Must |

### 1.3 入力支援（INPUT）

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-INPUT-01 | コマンド入力中に、コマンド名・サブコマンド・オプション・ファイルパスの候補をポップアップ表示する（シェルの補完とは独立） | Must |
| FR-INPUT-02 | 候補には 1 行説明（日本語／英語）を添える | Must |
| FR-INPUT-03 | 入力中のコマンドの意味を自然文で表示する "いまから何が起きるか" パネル（例: `git push -f` → "リモートの履歴を強制的に上書きします"） | Must |
| FR-INPUT-04 | 危険コマンドを検出し、実行前に確認ダイアログを出す。危険リストは編集可能・mod で追加可能 | Must |
| FR-INPUT-05 | 履歴検索（あいまい検索、CWD 絞り込み、成功したコマンドのみ等） | Must |
| FR-INPUT-06 | エラー出力を解析し、よくあるエラーには対処方法を提示する（例: `command not found` → インストール方法の提案） | Should |
| FR-INPUT-07 | 複数行コマンドのエディタ入力（Shift+Enter で改行、構文ハイライト） | Should |
| FR-INPUT-08 | 自然文 → コマンド変換、エラー説明、修正案（AI）。提案のみで自律実行はしない | Should（公式 mod `otterm.ai-assist`、同梱・既定オフ） |

### 1.4 ファイル操作（FILE）

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-FILE-01 | CWD に連動するファイルツリーパネルを表示できる | Must |
| FR-FILE-02 | ファイル／フォルダをダブルクリックで「開く」（既定アプリ、設定したエディタ、otterm 内プレビュー から選択） | Must |
| FR-FILE-03 | ファイルをターミナルにドラッグ&ドロップするとクォート済みパスが挿入される | Must |
| FR-FILE-04 | ファイルツリー上で `cd` / 新規作成 / リネーム / 削除（ゴミ箱へ）／コピー が GUI で行える。実行されたコマンド相当を表示し、学習につなげる | Should |
| FR-FILE-05 | テキスト・画像・Markdown・CSV の軽量プレビュー | Should |
| FR-FILE-06 | 出力内のファイルパス（`src/app.ts:42` 等）をクリックで該当行を開く | Must |

### 1.5 コマンドパレット・ワークフロー（PALETTE）

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-PAL-01 | すべての UI 操作・設定・mod コマンドをキーワードで検索して実行できるコマンドパレット | Must |
| FR-PAL-02 | 「よく使うコマンド」をボタン／スニペットとして登録でき、引数をフォーム入力できる（ワークフロー） | Should |
| FR-PAL-03 | ワークフローを mod として配布できる | Should |

### 1.6 外観カスタマイズ（LOOK）

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-LOOK-01 | 配色テーマ（16 色 + UI 色）を GUI で切替・編集できる | Must |
| FR-LOOK-02 | フォント（ファミリ、サイズ、太さ、行間、字間、フォールバック）を変更できる | Must |
| FR-LOOK-03 | ウィンドウ透過、ぼかし、背景画像、角丸、パディングを変更できる | Should |
| FR-LOOK-04 | タブバー・パネル・ステータスバーの位置と表示／非表示を変更できる | Must |
| FR-LOOK-05 | CSS 相当のスタイルシートでさらに細かく上書きできる | Should |
| FR-LOOK-06 | テーマを mod として配布できる | Must |

### 1.7 mod システム（MOD）

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-MOD-01 | mod を GUI から「入れる／外す／有効／無効」できる。再起動不要 | Must |
| FR-MOD-02 | mod は宣言された権限（ファイル読み書き、プロセス起動、ネットワーク等）の範囲でしか動けない | Must |
| FR-MOD-03 | mod は UI（パネル、ステータス項目、コンテキストメニュー、コマンド）、入力支援（補完、説明、危険判定）、テーマ、ワークフローを追加できる | Must |
| FR-MOD-04 | 公式レジストリからの検索・インストール・更新 | Should |
| FR-MOD-05 | ローカルフォルダ・Git URL・zip からのインストール | Must |
| FR-MOD-06 | mod 同士の依存関係と互換バージョンの解決 | Should |
| FR-MOD-07 | mod の開発モード（ホットリロード、ログ、デバッガ接続） | Should |
| FR-MOD-08 | "mod パック"（複数 mod + 設定をまとめた配布単位） | Could |

### 1.8 ガイド機能（GUIDE）

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-GUIDE-01 | 初回起動時にガイドレベル（0〜3）とシェルを選ぶオンボーディング | Must |
| FR-GUIDE-02 | ガイドレベルに応じて、ヒントの量・確認ダイアログの頻度・初期パネル構成が変わる | Must |
| FR-GUIDE-03 | 「はじめてのターミナル」チュートリアル（インタラクティブ、実際に打たせる） | Should |
| FR-GUIDE-04 | 画面上の UI 要素に `?` を出し、説明を表示できる（ヘルプモード） | Should |

## 2. 非機能要件（Non-Functional Requirements）

### 2.1 性能

| 項目 | 目標値 | 測定方法 |
| --- | --- | --- |
| キー入力から画面反映までの遅延 | p99 で 16 ms 以下（60 fps 1 フレーム以内） | 自動計測ツールで 1,000 回打鍵 |
| 大量出力のスループット | `cat` で 100 MB のテキストを 3 秒以内に流し切る | ベンチスクリプト |
| 起動時間 | コールドスタート 500 ms 以内（mod なし）、1 秒以内（同梱 mod あり） | 計測ログ |
| メモリ | 1 セッション常駐 150 MB 以下、10 セッションで 400 MB 以下 | OS のプロセス監視 |
| mod のオーバーヘッド | mod 1 つあたり入力遅延増加 1 ms 以下。超過 mod は警告表示 | プロファイラ |

### 2.2 信頼性

- 1 つの mod がクラッシュしてもターミナル本体とシェルプロセスは落ちない（mod は分離実行）
- 本体がクラッシュした場合も、シェルプロセスは分離プロセスで生かし、再起動後に再接続できる（デーモン方式、v1.x）
- 設定ファイルが壊れている場合は既定値で起動し、壊れた箇所を UI で示す
- クラッシュ時はローカルにクラッシュログを保存し、次回起動時に「GitHub Issue を作る」ボタンとログのコピーボタンを出す。外部サービスへの自動送信は行わない（判断 C11）

### 2.3 セキュリティ

- mod は宣言権限以外にアクセスできない（サンドボックス）
- mod からのネットワークアクセスは宣言ホストのみ、かつユーザーに表示
- クリップボード・ファイルシステム・プロセス起動は権限単位で初回に承認を求める
- レジストリ配布 mod は署名検証。未署名 mod はインストール時に警告
- シェル統合スクリプトは最小限・可読・ユーザーが確認できる
- テレメトリは **一切持たない**。otterm が自発的に外部へ接続するのは、ユーザーが許可した更新確認と、ユーザーが開いた mod ストアだけ（判断 H4）

### 2.4 アクセシビリティ

- スクリーンリーダー向けに、画面内容を行単位で読み上げ可能にする
- すべての操作をキーボードのみで完了できる
- 最小フォントサイズ・コントラスト比（WCAG AA）を満たす同梱テーマを用意

### 2.5 国際化

- UI 言語: 日本語・英語（v1）。文字列はすべて外部化し、mod でも翻訳を同梱できる
- 翻訳の仕組みは Fluent（`.ftl`）。複数形・変数を翻訳側で扱える（判断 C7）
- ヒント・説明文・コツメの台詞も翻訳対象。v1.0 の翻訳は PR ベースで受け付け、言語追加時に翻訳プラットフォームを検討（判断 G2）
- 右から左に書く言語（アラビア語、ヘブライ語）の UI は v1 では対応しない

### 2.6 配布・更新

- v1.0 の配布チャネルは **winget（MSI）、Homebrew cask（dmg）、AppImage** の 3 つ。deb / rpm / Flatpak は v1.1（Flatpak はサンドボックスから PTY を起動する制約があり別途設計。判断 A9）
- 自動更新（Tauri updater、差分更新、ユーザーが任意にオフ可）。署名鍵は CI のシークレットに保管し、ローテーション手順を文書化（判断 C10）
- 更新チャネルは stable と beta。nightly は GitHub Releases のみで自動更新の対象外
- ポータブル版（設定をインストールフォルダ内に置く）

## 3. ユーザーストーリー

### 初心者

- 授業で「ターミナルで `python main.py` を実行して」と言われたが、何をどこに打てばいいか分からない。otterm を開いたらファイルツリーがあり、`main.py` を右クリック → 「Python で実行」を選んだら、入力欄に `python main.py` が入って実行され、同時に「このコマンドは…」と説明が出た。
- `rm -r` を打ったら「このフォルダの中身がすべて消えます。ゴミ箱には入りません」と警告され、「ゴミ箱に送る」に切り替えられた。
- エラー `npm: command not found` が出たら、下に「Node.js が入っていないようです。インストールするには…」と手順が表示された。

### 日常利用者

- 10 個のタブを開いて作業しても、入力が引っかからない。
- `Ctrl+R` で履歴検索すると、このプロジェクトで打ったコマンドだけに絞れる。
- ビルドの長い出力がブロックごとに畳まれ、失敗したブロックだけ赤く目立つ。
- 出力の `src/foo.rs:120:5` をクリックしたら VS Code の該当行が開いた。

### 改造好き

- ステータスバーに今の Git ブランチと CPU 温度を出す mod を 20 行の TypeScript で書いた。
- 配色を Catppuccin にして、タブバーを左に縦置きし、背景を半透明にした。全部 GUI で終わった。
- 作ったテーマを `otterm mod publish` でレジストリに上げた。

### 配布者

- 新人向けに「Docker + Git + 社内 CLI の補完・説明・危険判定」を 1 つの mod パックにして配った。新人は URL を貼るだけで環境が整った。
