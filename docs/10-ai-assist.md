# 10. AI 補助仕様（AI Assist）

## 1. 位置づけ

AI 補助は **「コツメに聞ける」** という形で提供する。Warp のように AI が主役になるのではなく、コツメという相棒の能力の 1 つとして存在する。

| | Warp | otterm |
| --- | --- | --- |
| AI の立場 | 中心機能。エージェントがコマンドを実行する | コツメの能力の 1 つ。提案はするが実行はユーザー |
| 必須か | アカウント必須、クラウド必須 | 既定オフ。なくても辞書ベースの支援で動く |
| モデル | Warp が選ぶ | ユーザーのキー（BYOK）またはローカルモデル |
| 送信内容 | 利用規約の範囲 | 送る前に見せる。秘密情報は自動で伏せる |
| 自律実行 | あり | なし。多段タスクも 1 ステップずつ承認 |

### 1.1 原則

1. **説明が先、生成は後**。「何が起きるか」を分かりやすくするのが第一の仕事。コマンド生成はその延長
2. **提案はするが、Enter は押さない**。AI の出力は入力欄に入るだけ。実行はユーザー。これはコツメの設定（[08-character.md](08-character.md)）と同じ
3. **辞書で答えられるなら AI を呼ばない**。速くて、無料で、オフラインで、決定論的だから
4. **送る内容は見せる**。何がどこに送られるかを隠さない
5. **オフにできる、入れなくても困らない**。AI がないと成立しない UI を作らない

## 2. 3 層構造

| 層 | 仕組み | 対応できること | 遅延 | コスト |
| --- | --- | --- | --- | --- |
| Tier 0: 辞書 | 同梱 `dictionary-core` と mod 辞書。パターン照合 | 既知コマンドの説明、既知エラーの助言、危険判定 | 0 ms | 無料、オフライン |
| Tier 1: ローカルモデル | Ollama / llama.cpp 互換サーバーに接続。7B 級の量子化モデルを推奨 | 自然文 → コマンド、未知エラーの説明、出力の要約 | 1〜5 秒 | 無料、オフライン、GPU があると快適 |
| Tier 2: クラウドモデル | ユーザーの API キー。Claude、OpenAI、Gemini、および OpenAI 互換エンドポイント | Tier 1 と同じことを高精度で。長い出力の解析、多段タスクの計画 | 1〜3 秒 | ユーザー負担 |

- 問い合わせは Tier 0 → 1 → 2 の順に試す。Tier 0 で確信度が高ければそこで止まる
- ユーザーは「ローカルのみ」「クラウドのみ」「自動」を選べる。既定は、AI を有効化した時点で選んだプロバイダのみ
- 推奨ローカルモデルのリストは本体に埋め込まず、レジストリから配信して更新する（モデルの進歩が速いため）

## 3. 機能

### 3.1 自然文 → コマンド（「コツメ、〜して」）

- 起動方法（判断 F1）: **`Ctrl+Shift+Space` を押すか、コツメをクリック**すると、入力行の下に小さな質問プロンプトが吹き出しとして開く。そこに自然文を書く（例: 「このフォルダの png を全部 jpg に変換」）
  - 入力欄で `?` から始める方式は採用しない。zsh では `?` がグロブ文字でエラーになり、シェルの行編集をそのまま使う方針（[03-core-features.md](03-core-features.md) §8.0）とも衝突する。`?` プレフィックスは設定でオンにできるオプション（既定オフ）として残し、オンのときは実行直前（before-execute）で otterm が引き取る
  - CLI からは `otterm ask "質問"` でも同じ
- 結果は **コマンド + 1 行説明 + 危険バッジ** の 3 点セットで吹き出しに出る
- 「入力欄に入れる」ボタンで挿入。実行はしない
- 生成されたコマンドにも **danger-guard が必ず走る**。AI が `rm -rf` を返しても確認が出る
- 生成コマンドのオプションを辞書と照合し、辞書にないオプションには「辞書で確認できないオプションです」と注記する（存在しないフラグの捏造対策）

### 3.2 エラーの説明と修正案

- ブロックが非 0 で終わったとき、まず Tier 0 の `error-hint` が動く
- 辞書で解決できなかった場合のみ、助言カードに「コツメに聞く」ボタンが出る。**自動では送らない**
- 送る内容: 実行したコマンド、出力（末尾 200 行まで）、終了コード、CWD、OS とシェルの種類。送信前にプレビュー
- 返答は「原因」「直し方」「修正済みコマンド」の 3 段。修正済みコマンドは入力欄に入れられる

### 3.3 直前のコマンドを直す（`fix`）

- 失敗直後に `fix` と打つ（または `Ctrl+Shift+.`）と、直前のブロックを文脈に修正案を出す
- 単純なタイポ（`gti` → `git`）は Tier 0 で即答。それ以外は Tier 1 以上

### 3.4 出力について聞く

- 出力範囲を選択して右クリック → 「コツメに聞く」。選択範囲だけを送る
- 用途: ログの読解、スタックトレースの要点、`--help` の長い出力から目的のオプションを探す

### 3.5 「今なにしてた？」

- セッションの最近のブロック（コマンドと終了コードのみ。出力は含めない）を要約する
- 用途: 作業の中断からの復帰、日報、チュートリアルの振り返り

### 3.6 ステップ実行モード（オプトイン）

Warp のエージェントモードに相当するが、設計が違う。

1. ユーザーが目的を書く（例: 「このリポジトリを clone してテストを通して」）
2. コツメが **計画（ステップの一覧）** を出す。各ステップはコマンドと説明
3. ユーザーが「このステップを実行」を押す。1 つずつ。「全部実行」ボタンは置かない
4. 実行結果（ブロック）を見て、コツメが次のステップを調整する。失敗したら止まる
5. いつでも「やめる」で中断。実行済みステップの一覧が残る

- 既定オフ。設定で有効化し、初回に説明を表示
- ワークスペース設定でチームとして禁止できる（`terminal.write` と同じ扱い）
- 1 ステップの実行はユーザーのクリックなので、コツメの「Enter を押さない」原則を破らない

## 4. 送信内容と秘密情報の扱い

### 4.1 送るもの、送らないもの

| 送る（機能ごとに必要な範囲のみ） | 送らない |
| --- | --- |
| 入力した質問文 | 環境変数の **値**（名前のみ可） |
| 対象ブロックのコマンドと出力 | スクロールバック全体 |
| CWD、OS、シェル種別 | ファイルの中身（ユーザーが明示的に選択した場合のみ） |
| 「まとめ」では直近 10 件のコマンドと終了コード（各 200 文字まで、出力なし） | 他のタブ・セッションの内容 |
| | クリップボード |

### 4.2 自動マスク

送信前に次を正規表現で検出し、`[REDACTED]` に置き換える（`ai.redact_secrets = false` で止められる）。実装は `crates/otterm-app/src/ai.rs` の `redact`。

- API キー・トークン風の文字列（`sk-`、`ghp_` などの GitHub トークン、`AKIA`、Slack の `xox…`、Google の `AIza…`、PEM の秘密鍵ブロック、32 文字以上の英数字の並び）
- `password=`、`token=`、`secret=`、`api_key=` などの値
- ホームフォルダのパスは `~` に縮める（ユーザー名を送らない）
- **未実装**: メールアドレスと IP アドレスのマスク、`~/.ssh/` や `.env` の中身が出力に含まれるときの行単位のマスク、接続文字列、`Authorization: Bearer` の短いトークン。プレビューで目視するのが前提

### 4.3 プレビュー

- **既定では毎回**、送信内容を全文表示して確認を求める（`ai.preview_first_n = 0`、1.2.0）。`preview_first_n = 5` のように数を置くと、その回数のあとは「送信内容を見る」リンクに縮む。README の「送る前に毎回中身を見せる」はこの既定を指す
- プレビューにはプロバイダ名と、送信先ホストを明記
- 「このワークスペースでは AI を使わない」を 1 クリックで設定できる

### 4.4 ログ

- 送信した内容と返答はローカルの `ai-log.jsonl` に残す（既定 30 日、オフ可）。ユーザーが後から「何を送ったか」を確認できる
- otterm の開発者には何も送られない。テレメトリは AI 機能を含めて既定オフ

## 5. 提供形態

- 公式 mod `otterm.ai-assist` として実装。**インストーラに同梱するが既定オフ**
- オンボーディングの最後に「コツメに AI の力を貸しますか？」と聞く。「あとで」が既定の選択肢
- 有効化するとプロバイダ選択画面が出る。ローカル（Ollama）、各クラウドのキー入力、OpenAI 互換 URL
- Ollama の検出（`localhost:11434` への接続確認）は **この画面を開いたときにだけ** 行う。何もしていないのにローカルポートへ接続しない（判断 F2）
- コアには AI の知識を一切置かない。`otterm.ai-assist` を削除しても他の機能に影響しない

## 6. コツメとの統合

| 場面 | コツメの振る舞い |
| --- | --- |
| 問い合わせ中 | `thinking`。石を持ち上げて考える。吹き出しに「考えています…」 |
| 返答 | 吹き出しカードにストリーミング表示。コマンドはコードブロック、ボタン付き。**コードブロックが 2 つ以上になる長い回答は自動で下パネルに展開**し、吹き出しには要約 1 行と「パネルで見る」を残す（判断 F5） |
| 危険なコマンドを返したとき | `alert` に切り替え、危険バッジを赤く表示 |
| 失敗（接続エラー、キー無効） | 「つながりませんでした。設定を確認しますか？」。叱らない |
| AI オフのとき | 「コツメに聞く」ボタン自体を出さない。Tier 0 の助言だけ出す |

## 7. mod API

他の mod も、ユーザーが設定したプロバイダを借りられる。権限 `ai` を宣言し、承認を得る必要がある。

```ts
// 権限 ai が必要。プロバイダはユーザー設定に従う（mod は選べない）
const res = await ctx.ai.complete({
  purpose: "git コミットメッセージの提案",   // プレビューに表示される用途
  prompt: `次の差分からコミットメッセージを 1 行で:\n${diff}`,
  context: { include: ["cwd"] },             // 送る文脈を明示
  maxTokens: 200,
});
ctx.terminal.insert(`git commit -m "${res.text}"`);
```

- `ctx.ai.complete` は毎回ユーザーに「この mod が AI に問い合わせます（用途: …）」を表示する。頻度制限あり（1 mod あたり 1 分に 10 回）
- mod は独自のキーを持たない。ユーザーのプロバイダを使う。独自にクラウドへ送りたい mod は通常の `network` 権限で、送信先ホストを宣言する

## 8. 品質の担保

- 評価セット: 日本語・英語それぞれ 300 問の「自然文 → 期待コマンド」ペア。OS 別。手元で回してローカルモデルとクラウドの正答率を記録する（自動テストにはしない。判断 L2）
- 危険コマンド生成の確認: 「全部消して」のような指示に対して、生成結果に danger-guard が必ず反応すること
- 捏造オプション検出率: 辞書と照合して存在しないフラグを含む回答の割合を追跡
- 遅延: Tier 2 で初回トークンまで 2 秒以内（UI 側の目標。モデル側は制御できないため、超えたら「時間がかかっています」を出す）

## 8.1 実装（2026-10-12）

- 橋渡しはホスト（判断 M22）: `crates/otterm-app/src/ai.rs` が各プロバイダへのストリーミング、OS のキーチェーン（keyring、サービス名 `otterm-ai`）、自動マスク、`<データ>/logs/ai-log.jsonl`、1 分 10 回の制限、ワークスペース単位のオフ（`state/ai-off-workspaces.json`）を受け持つ
- Claude は既定で `claude-opus-5-5`（`[ai] model` で変更可）、`output_config.effort = "low"`、拒否時の自動切り替え（`fallbacks: "default"`）を付ける。OpenAI・Gemini・OpenAI 互換はモデル名の設定が必須。Ollama の既定は `qwen2.5-coder:7b`
- 送信前のプレビューは UI が出す。otterm 以外の mod は毎回、`otterm.ai-assist` も既定（`[ai] preview_first_n = 0`）では毎回で、数を置いたときだけその回数まで。プレビューから「このワークスペースでは AI を使わない」を選べる
- `context.include` の `lastBlock` は直前に終わったブロックのコマンド・終了コード・出力の末尾 200 行、`selection` はアクティブなペインの選択範囲
- 評価セットは `tests/ai-eval/`（100 問、判断 F3）。ローカルの OpenAI 互換サーバー（Ollama）を既定にし、それ以外の送り先では課金の警告を出す

## 9. やらないこと

- AI がユーザーの代わりにコマンドを実行すること（ステップ実行モードでもクリックは人間）
- アカウント登録を要求すること
- ユーザーの入力や出力を otterm 側のサーバーに送ること（サーバーを持たない）
- AI が前提の UI（AI をオフにすると空欄になる画面）を作ること
- 「AI が言ったから安全」という表示。危険判定は常に辞書ベースの danger-guard が最終判断

## 10. Otterm の方向性と合うか

合う。ただし条件付き。

- 「コツメに聞ける」は、コツメが UI に住んでいる otterm にとって最も自然な AI の形。Warp が AI のためにブロック UI を作ったのに対し、otterm はすでにある相棒に能力を足すだけで済む
- 「提案はするが実行しない」は、初心者を守る otterm の姿勢そのもの。エージェントの自律実行で Warp に並ぼうとすると、この姿勢を捨てることになる。並ばない
- ローカル優先・BYOK は、オープンでアカウント不要という otterm の立場と一致する
- 完成度で Warp に「引けを取らない」と言えるのは、エラー説明・自然文変換・修正案・出力の読解の 4 つ。自律エージェントの範囲では Warp の方ができることが多いが、それは意図した差

つまり otterm の AI は「Warp と同じことができる」ではなく「Warp より安心して任せられる」で勝負する。
